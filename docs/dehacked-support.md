# DeHackEd/BEX support (partial)

The engine loads external DeHackEd/BEX patches and embedded `DEHACKED` lumps,
with session-local definitions, actor properties, monster death/raise states
and selected flags/actions. **This is a supported subset, not complete DeHackEd support.**
Unsupported changes fail explicitly. The original Sunlust patch now loads,
including its non-solid Keen `VileChase` loop, map titles and story strings.

## Definition model

`Vanilla()` creates independent original Doom 1.9 tables: 137 Thing slots,
967 actor/effect/weapon states, nine weapons, four ammo types, 109 sounds,
138 sprites, music names, English strings, cheat codes, par times and misc
rules. The canonical tables are generated by compiling and reading the original
Linux Doom 1.10 constant data; action functions in that generator are empty
stubs and never executed. Source-file hashes, including compiler-discovered
local header dependencies, are recorded in the generated file.

Thing slots, map editor numbers and state IDs are separate domains. DeHackEd
`Thing 25` is zero-based slot 24, Commander Keen; its map editor number is 72.
Frame numbers remain original Doom numbers across actors, effects and weapons.
Monster walking speed remains an integer and missile speed remains fixed point;
radius/height remain 16.16 values. Weapon no-ammo is 5, not ammo slot 4.

`Apply` returns a new definitions set. Getters return values, and `Snapshot`,
`Sources`, `Diagnostics` and `VanillaSourceHashes` return owned copies. Defaults,
base definitions and parsed patches can be shared by concurrent sessions.
`FieldWasSet` preserves explicit writes even when they equal the default; Boom
uses this distinction for actor flag and health-limit behavior. `Digest` hashes
resolved data and write markers deterministically, preserving arbitrary legacy
string bytes. It excludes patch filenames and comments.

For example, inside code with access to the internal package:

```go
patch, err := dehacked.Parse("mod.deh", patchBytes)
if err != nil {
    return err
}
defs, err := dehacked.Vanilla().Apply(patch)
if err != nil {
    return err
}
keen, ok := defs.ThingByNumber(25)
// keen now contains the patched definition; no game has been modified.
```

## Parser scope and behavior

The initial target is format-6 text DeHackEd for Doom 1.9 (Doom version 19/21,
v2.3/v3.0 text headers) plus core Boom/BEX. Headerless BEX is accepted too.

- Classic blocks: `Thing`, `Frame`, `Pointer`, `Ammo`, `Weapon`, `Misc`,
  `Sound`, `Sprite`, `Cheat` and byte-counted `Text`.
- Core BEX: `[CODEPTR]`, `[STRINGS]`, `[PARS]`; numeric and supported symbolic
  Thing `Bits`, including Boom translucency and translation aliases.
- Decimal, hexadecimal and octal complete 32-bit words, including two's-complement
  encodings such as `0xffffffff` for -1. Out-of-range values, trailing numeric
  junk, invalid slots and unsupported gameplay fields/actions are errors.
- Comments, CRLF, missing final newlines, repeated blocks and ordered patch
  application. `Text` lengths count bytes, ignore carriage returns as the native
  parser does, and do not interpret payload lines as patch syntax. Embedded NUL
  bytes/binary patches are rejected.
- Explicit caller-supplied `INCLUDE` resolution, cycle/depth/aggregate-byte bounds,
  and change, diagnostic and source-count limits. The parser performs no file or
  network access. WhackEd `Engine config`/`IWAD` metadata does not load resources.

Compatibility details verified against DSDA:

- Classic Pointer copies read the **compiled original action**, including across
  patch files. The Pointer ordinal is not the target state; `(Frame N)` is.
  BEX uses bare mnemonics such as `VileChase` or `NULL`, not `A_VileChase`.
- Resource renames through classic `Text` are one-shot for a sprite, sound or
  music slot across the patch stack. Non-resource literal replacements are
  retained for presentation consumers, and known English strings are resolved.
- BEX string continuation preserves spaces before a trailing backslash, trims
  indentation on the next line and converts `\n`/`\N` to line feeds. Named
  strings outside the baseline catalog are retained with a diagnostic for the
  eventual consumer; their acceptance is not a claim that the engine displays them.
- `INCLUDE NOTEXT` follows the native legacy line skipper: after encountering
  a `Text` block it skips through the next line beginning with a literal space,
  or through EOF. Blank lines do not end that skip. A diagnostic makes this
  behavior visible, and parsing resumes in the including file.
- The portable Sound fields used here are `Value` (priority) and `Zero 2` (pitch).
  Executable offsets, old pointer/cache fields, `Zero 3`/`Zero 4`, and Sprite
  offsets are explicitly diagnosed and ignored as in the DSDA parser.

Zero-duration state chains, self-loops, infinite durations and null states are
preserved as data; the parser does not run them. Binary executable patches,
MBF actions/helper blocks, DEHEXTRA slots and MBF21 fields/actions are outside
this milestone. Raw numeric flag words retain their bits; this does not establish
support for an extended feature encoded in those bits. Strict errors replace
the reference parser's unsafe overflow or partial-conversion behavior.

## Verification

The [source-pinned results](dehacked-parser-results.json) record **42 passing
native comparisons and 69,266 definition rows** against DSDA-Doom 0.27.5:
twenty-one fixtures each in Doom 1.9 (`-complevel 2`) and Boom (`-complevel 9`)
modes. This includes the complete, unmodified original Sunlust patch. Its actor
properties, state loop, cross-type `VileChase` assignments and all changed
strings match the native parser's resolved data.

Every case compares all canonical actor/state/weapon/ammo rows, resources and
par times, supported sound fields, patched English strings/cheats, and explicit
actor Bits/health/BFG override markers. The native observer exits after patch
postprocessing and before gameplay. Resource/action names compare without case;
DSDA's shared Raven no-ammo sentinel and internal flags are mapped to canonical
Doom representations. `boom_translucent_sprites 0` disables automatic cosmetic
flags on unpatched actors; explicitly patched Bits are compared in full.
This is a definition/parser proof, not a simulation or presentation proof.

Unit and race tests, `go vet`, a final fuzz run with 170,715 executions, and
the existing runtime/app/network Go suites pass. Generated defaults reproduce
byte-for-byte. These checks do not reclassify the separately recorded vanilla
demo corpus or Boom campaign proofs.

```sh
go test -race ./internal/dehacked
go vet ./internal/dehacked
go test ./internal/dehacked -run '^$' -fuzz FuzzParseApply -fuzztime=15s

# Optional canonical regeneration; no IWAD is needed.
python3 scripts/gen_dehacked_defaults.py --doom-source /path/to/linuxdoom-1.10
```

## Actor-property gameplay integration

`doomruntime.newGameWithDefinitions` validates a resolved patch set before map
initialization or RNG changes, then installs an owned per-game property cache.
It currently supports existing map monsters and barrels: spawn health, reaction
time, pain chance, walking speed, radius, height and mass. Unwritten properties
retain the existing engine behavior. Barrel pain/speed changes are rejected until
their state/action consumers are integrated. Monster speed is converted from integer
units; dimensions retain their original fixed-point values, including zero.

These values feed actual spawn, walking, collision, aim/LOS, damage thrust,
overkill thresholds, corpse dimensions, resurrection and respawn consumers.
Nightmare still overrides initial reaction time with zero; nightmare respawning
keeps Doom's fixed 18-tic reaction delay. An explicitly patched zero pain chance
still consumes the native pain RNG roll. Zero-speed monsters keep successful-walk
RNG/timing. Ceiling spawns use patched height. Sessions do not mutate shared tables.

Unsupported fields, including explicit writes of their default values, fail
validation. Supported scalar ranges are positive health/mass, nonnegative
reaction/dimensions, pain chance 0–256 and walking speed 0–32767; the parser
preserves the broader original 32-bit values independently.

## Patched states and actions

All nineteen map monster kinds (including Commander Keen) and barrels can use
canonical spawn, see, pain, melee, missile, death, overkill and raise states.
They consume patched `Duration`, `Next frame` and classic/BEX code pointers.
State zero removes an actor on entry; a zero missile root disables missile
attacks. A zero spawn root is rejected. The destination state's original
sprite/frame metadata follows redirects, including cross-type redirects.
Unmodified actor types keep their existing thinker paths.

The dispatcher covers the original monster actions, including `VileChase`,
`VileTarget`, `VileAttack`, `KeenDie`, `BossDeath`, `Fall`, `Scream`, `XScream`,
`PainDie`, `Explode`, the three mancubus attacks, revenant attacks and the
existing hitscan/projectile attacks. `SkullAttack` remains restricted to lost
souls until cross-type actor damage and zero-damage collision behavior are
integrated. Projectile/effect/player/weapon state machines are separate and
cannot be redirected or patched through this interface.

`VileChase` uses the calling actor's speed and the arch-vile definition's search
radius, then enters the original arch-vile heal chain. Resurrection restores
original definition flags, health and raise state. Death clears shootability,
adds corpse/dropoff flags, and retains solidity until `Fall`; crusher gibs and
cold checkpoints retain these per-instance changes. Fast mode halves the
original demon state slots, including cross-type redirects, while Boom retains
one-tic durations.

Supported flag consumers include solidity, shootability, ambush, blockmap links,
ceiling spawning, gravity, float/dropoff movement, noclip, shadows, blood,
kill/item counts, corpse state and deathmatch spawning. Pickup/special, NOSECTOR,
SLIDE, TELEPORT, MISSILE, initial SKULLFLY, translation, translucency and extended
flags are rejected. This is a partial flag implementation, not arbitrary Bits
support. Actor sight/pain/death/active/attack sound slots accept mapped existing
sounds or zero; sound-table/resource modifications remain unsupported.

Actions execute on state entry, not initial spawning. Zero-tic chains execute
within the same tic, including chains longer than the former 16-frame cap.
Duration `-1` remains infinite. Pure zero-tic cycles are rejected during
validation; a bounded transition budget reports action-driven recursion as a
runtime error. Durations below `-1` are not enabled in gameplay.

Sprite/Frame edits, editor-number changes, projectile/effect/player/weapon
states, general strings/resources, weapon/ammo rules and miscellaneous gameplay
rules remain unsupported. Barrel pain/speed modifications are still rejected.
Supported presentation strings are `HUSTR_1` through `HUSTR_32` in the level/music
catalog and `C1TEXT`–`C6TEXT` / `E1TEXT`–`E4TEXT` in story screens. Catalogs are
cloned per session.

## Launcher, campaign and checkpoints

Both launchers accept repeated or comma-separated `-deh` paths. All embedded
`DEHACKED` lumps load in WAD/directory order, followed by external patches in
argument order. This follows DSDA 0.27.5's explicit-content order. `-nodeh` skips
embedded patches while retaining explicit external patches. No sidecar or
autoload-directory search is performed. External `INCLUDE` paths resolve relative
to the including file; embedded includes have no filesystem resolver. The entire
stack is limited to 16 MiB of read patch data and 100,000 changes.

```sh
go run . -wad DOOM2.WAD -file maps.wad -deh monsters.deh -deh extra.bex
# Skip embedded patches, but still apply the explicitly requested patch.
go run . -wad DOOM2.WAD -file maps.wad -nodeh -deh monsters.deh
```

Classic patch blocks should have blank separator lines for native compatibility.
Runtime capability errors are reported before starting gameplay, including when
launching through the IWAD picker. The public runtime constructors also surface
unsupported definitions before allocating gameplay resources or changing RNG.

Definitions travel through `Options` into new levels, rebirths and restored games.
Save version 47 and keyframe version 34 carry the resolved definition digest
and persistent actor flags;
loading requires the same definitions to be loaded again. Saves do not bundle
external patch files. Patched checkpoints older than version 47 must be replayed
from the map start; unpatched saves retain the usual compatibility window. A mismatch is rejected before installing the snapshot or
changing RNG in either host. Authoritative network sessions also require the
same locally loaded definition identity, as described below. Legacy peer-driven
sessions continue to reject patches.

Focused Go tests cover actor properties, state roots, code-pointer RNG classes,
zero-tic/infinite/null states, recursion limits, loader order/includes, launcher
errors, both hosts' checkpoint identity, and rejection before RNG changes.
The affected runtime/app/network/launcher/session suites pass; Raylib launcher
tests and an actual headless launcher demo also pass. These checks do not retag
older vanilla corpus or Boom campaign receipts with the new source identity.

D2All recordings (`slallk45115` and `slallj45115`), the archive's documented MAP26
start fix and the original Sunlust patch. `--patched` loads that exact patch

```sh

  --iwad /path/to/doom2.wad --reference /path/to/instrumented/dsda-doom \
  --patched --out /tmp/gddoom-patched-coop-campaign
```

The default matrix runs both recordings continuously and with cold save/keyframe

output directory; `scripts/combine_patched_coop_campaign.py DIR1 ... DIR6 --out
results.json` requires six complete passing reports with identical source,
verifier and capture binaries, matching per-recording references, complete

The movie ends in MAP30 intermission, so it does not cover that map's finale.

All six complete replays pass against DSDA 0.27.5: both original console
recordings, each continuous and with cold saves/keyframes. The
[combined receipt](dehacked-coop-campaign-results.json) pins the verified Go

It records 3,917,886 command-frame comparisons, 3,672,954 active-world rows and
764 cold restores, including intermissions, story screens, player deaths and
subsequent-map rebirths. Each replay covers all 32 maps and five story screens.
No replacement or appended commands are included. This establishes offline
patched co-op demo parity for this campaign. Live definition negotiation is
verified separately below; this campaign receipt retains its original source pin.

The MAP22 investigation corrected generic monster retargeting after a player's
death. The next walk frame must be installed before `A_Chase`; a successful
direct player reacquisition then returns without movement, chase RNG, or
clearing `JUSTATTACKED`. This also applies when attacks, pain or raise sequences
enter a run frame. Unit regressions and a 394-frame native post-death window
cover the walk and attack-expiry cases. The simulation compatibility ID advances
to `gd-doom-authority-dev-37` for this behavior change.

For native diagnosis, `GD_COOP_CAPTURE_FROM_COMMAND=N` suppresses earlier trace
output while still executing every original command. Indexed full rows can be
written with `GD_COOP_CANONICAL_OUT`. Official verifiers scrub diagnostic window
and continuation settings, pin the native observer/binary, and replay from
command one. Regenerated full reference traces are byte-identical with the
window setting absent.

## Live patched co-op definition negotiation

Authoritative servers and clients negotiate a resolved `DefinitionDigest` in
addition to engine version, ordered WAD hashes, map and rules. Discovery compares
the locally loaded definitions; player and spectator joins reject a mismatch
before admission. The digest includes explicit field writes and all resolved
strings/states/actor definitions, preserving the runtime's distinction between
an explicit default and an unwritten field. Comments and filenames do not affect
it. Empty means no applied patch; it does not mean "accept the server's patch."
No patches or local paths are supplied by the remote server.

```sh
# Server and client load the same ordered WADs and external patch stack.
go run ./cmd/gdserver -wad DOOM2.WAD -file maps.wad -deh monsters.deh
# Use the server address printed at startup.
go run . -wad DOOM2.WAD -file maps.wad -deh monsters.deh -connect 127.0.0.1:6671
```

Both launchers and `gdserver` apply embedded DEHACKED lumps first, then repeated
or comma-separated `-deh` paths. `-nodeh` skips embedded patches while retaining
explicit patches. External includes retain the existing relative-path rules.
Unsupported definitions fail before the server starts listening. Definitions
are immutable and their digest is cached safely for concurrent discovery and
per-tick snapshots.

The verified identity is retained through reconnects and map changes. Snapshot
baselines independently carry and validate it before modifying the client world;
rebuilds preserve the same local definitions. The authority compatibility ID is
`gd-doom-authority-dev-38`, and baseline version 3 includes the identity in its
generated binary schema. Older engines must update before joining. Save version
47 and keyframe version 34 are unchanged.

Managed room catalogs and uploaded WAD stacks derive their embedded definition
identity locally and preserve it through pack metadata, room JSON and worker
verification. Managed rooms do not distribute or configure external patch files;
use embedded patches for those rooms, or configure a direct server and load the
external patches independently on each client. The legacy peer/tic-stream
protocol still rejects patches because it has no definition negotiation.

Regression coverage includes matching/equivalent/mismatched patch admission,
players and spectators, browser discovery, a real TCP/WebSocket two-player co-op
server, embedded/external/include ordering and `-nodeh`, reconnecting to the same
body/inventory, menu installation, patched snapshot state and rejection before
RNG changes, campaign rebuilds, and catalog/upload/room JSON identities. These
live checks do not retag the earlier DSDA campaign evidence.
