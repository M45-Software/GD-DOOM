# DeHackEd/BEX foundations

The `internal/dehacked` package implements patchable definition data and a
transactional text parser. The gameplay engine now has an internal actor-property
integration stage; **the launcher does not load patches yet**. This does not make
patched WADs playable or claim Sunlust MAP30 gameplay/demo parity. State/action
dispatch, resource loading, saves and multiplayer integration remain subsequent work.

## Definition model

`Vanilla()` creates independent original Doom 1.9 tables: 137 Thing slots,
967 actor/effect/weapon states, nine weapons, four ammo types, 109 sounds,
138 sprites, music names, English strings, cheat codes, par times and misc
rules. The canonical tables are generated by compiling and reading the original
Linux Doom 1.10 constant data; action functions in that generator are empty
stubs and never executed. Source-file hashes, including compiler-discovered
local header dependencies, are recorded in the generated file.

Thing slots, map editor numbers and state IDs are separate domains. DeHackEd
`Thing 25` is zero-based slot 24, Commander Keen; its map editor number is 72.
Frame numbers remain original Doom numbers across actors, effects and weapons.
Monster walking speed remains an integer and missile speed remains fixed point;
radius/height remain 16.16 values. Weapon no-ammo is 5, not ammo slot 4.

`Apply` returns a new definitions set. Getters return values, and `Snapshot`,
`Sources`, `Diagnostics` and `VanillaSourceHashes` return owned copies. Defaults,
base definitions and parsed patches can be shared by concurrent sessions.
`FieldWasSet` preserves explicit writes even when they equal the default; Boom
uses this distinction for actor flag and health-limit behavior. `Digest` hashes
resolved data and write markers deterministically, preserving arbitrary legacy
string bytes. It excludes patch filenames and comments.

For example, inside code with access to the internal package:

```go
patch, err := dehacked.Parse("mod.deh", patchBytes)
if err != nil {
    return err
}
defs, err := dehacked.Vanilla().Apply(patch)
if err != nil {
    return err
}
keen, ok := defs.ThingByNumber(25)
// keen now contains the patched definition; no game has been modified.
```

## Parser scope and behavior

The initial target is format-6 text DeHackEd for Doom 1.9 (Doom version 19/21,
v2.3/v3.0 text headers) plus core Boom/BEX. Headerless BEX is accepted too.

- Classic blocks: `Thing`, `Frame`, `Pointer`, `Ammo`, `Weapon`, `Misc`,
  `Sound`, `Sprite`, `Cheat` and byte-counted `Text`.
- Core BEX: `[CODEPTR]`, `[STRINGS]`, `[PARS]`; numeric and supported symbolic
  Thing `Bits`, including Boom translucency and translation aliases.
- Decimal, hexadecimal and octal complete 32-bit words, including two's-complement
  encodings such as `0xffffffff` for -1. Out-of-range values, trailing numeric
  junk, invalid slots and unsupported gameplay fields/actions are errors.
- Comments, CRLF, missing final newlines, repeated blocks and ordered patch
  application. `Text` lengths count bytes, ignore carriage returns as the native
  parser does, and do not interpret payload lines as patch syntax. Embedded NUL
  bytes/binary patches are rejected.
- Explicit caller-supplied `INCLUDE` resolution, cycle/depth/aggregate-byte bounds,
  and change, diagnostic and source-count limits. The parser performs no file or
  network access. WhackEd `Engine config`/`IWAD` metadata does not load resources.

Compatibility details verified against DSDA:

- Classic Pointer copies read the **compiled original action**, including across
  patch files. The Pointer ordinal is not the target state; `(Frame N)` is.
  BEX uses bare mnemonics such as `VileChase` or `NULL`, not `A_VileChase`.
- Resource renames through classic `Text` are one-shot for a sprite, sound or
  music slot across the patch stack. Non-resource literal replacements are
  retained for presentation consumers, and known English strings are resolved.
- BEX string continuation preserves spaces before a trailing backslash, trims
  indentation on the next line and converts `\n`/`\N` to line feeds. Named
  strings outside the baseline catalog are retained with a diagnostic for the
  eventual consumer; their acceptance is not a claim that the engine displays them.
- `INCLUDE NOTEXT` follows the native legacy line skipper: after encountering
  a `Text` block it skips through the next line beginning with a literal space,
  or through EOF. Blank lines do not end that skip. A diagnostic makes this
  behavior visible, and parsing resumes in the including file.
- The portable Sound fields used here are `Value` (priority) and `Zero 2` (pitch).
  Executable offsets, old pointer/cache fields, `Zero 3`/`Zero 4`, and Sprite
  offsets are explicitly diagnosed and ignored as in the DSDA parser.

Zero-duration state chains, self-loops, infinite durations and null states are
preserved as data; the parser does not run them. Binary executable patches,
MBF actions/helper blocks, DEHEXTRA slots and MBF21 fields/actions are outside
this milestone. Raw numeric flag words retain their bits; this does not establish
support for an extended feature encoded in those bits. Strict errors replace
the reference parser's unsafe overflow or partial-conversion behavior.

## Verification

The [source-pinned results](dehacked-parser-results.json) record **42 passing
native comparisons and 69,266 definition rows** against DSDA-Doom 0.27.5:
twenty-one fixtures each in Doom 1.9 (`-complevel 2`) and Boom (`-complevel 9`)
modes. This includes the complete, unmodified original Sunlust patch. Its actor
properties, state loop, cross-type `VileChase` assignments and all changed
strings match the native parser's resolved data.

Every case compares all canonical actor/state/weapon/ammo rows, resources and
par times, supported sound fields, patched English strings/cheats, and explicit
actor Bits/health/BFG override markers. The native observer exits after patch
postprocessing and before gameplay. Resource/action names compare without case;
DSDA's shared Raven no-ammo sentinel and internal flags are mapped to canonical
Doom representations. `boom_translucent_sprites 0` disables automatic cosmetic
flags on unpatched actors; explicitly patched Bits are compared in full.
This is a definition/parser proof, not a simulation or presentation proof.

Unit and race tests, `go vet`, a final fuzz run with 170,715 executions, and
the existing runtime/app/network Go suites pass. Generated defaults reproduce
byte-for-byte. These checks do not reclassify the separately recorded vanilla
demo corpus or Boom campaign proofs.

```sh
go test -race ./internal/dehacked
go vet ./internal/dehacked
go test ./internal/dehacked -run '^$' -fuzz FuzzParseApply -fuzztime=15s

# Optional canonical regeneration; no IWAD is needed.
python3 scripts/gen_dehacked_defaults.py --doom-source /path/to/linuxdoom-1.10
```

For independent native verification, use an isolated DSDA 0.27.5 source copy.
Append an absolute-path include of
`scripts/visual_compare/dsda_dehacked_probe.inc` to `src/d_deh.c`. Immediately
after `PostProcessDeh();` in `src/d_main.c`, add:

```c
{ extern void GD_DehackedProbe(void); GD_DehackedProbe(); }
```

Build that reference using its normal CMake/dependency instructions, then run:

```sh
python3 -B scripts/verify_dehacked_parser.py \
  --reference /path/to/instrumented/dsda-doom --iwad /path/to/doom2.wad \
  --sunlust-wad /path/to/sunlust.wad --out /tmp/gddoom-dehacked-parser
```

The verifier builds one Go comparison executable, creates fixtures, retains native
table dumps/logs and guards source/reference/observer identities. Omitting
`--sunlust-wad` runs the synthetic cases. It suppresses automatic IWAD patches
and explicitly loads each test's unchanged patch files. Commercial IWADs and
the external community patch are not bundled.

## Actor-property gameplay integration

`doomruntime.newGameWithDefinitions` validates a resolved patch set before map
initialization or RNG changes, then installs an owned per-game property cache.
It currently supports existing map monsters and barrels: spawn health, reaction
time, pain chance, walking speed, radius, height and mass. Unwritten properties
retain the existing engine behavior. Barrel pain/speed changes are rejected until
their state/action consumers are integrated. Monster speed is converted from integer
units; dimensions retain their original fixed-point values, including zero.

These values feed actual spawn, walking, collision, aim/LOS, damage thrust,
overkill thresholds, corpse dimensions, resurrection and respawn consumers.
Nightmare still overrides initial reaction time with zero; nightmare respawning
keeps Doom's fixed 18-tic reaction delay. An explicitly patched zero pain chance
still consumes the native pain RNG roll. Zero-speed monsters keep successful-walk
RNG/timing. Ceiling spawns use patched height. Sessions do not mutate shared tables.

This stage rejects unsupported fields, including explicit writes of default
values, rather than silently ignoring them. Player/projectile/pickup definitions,
editor-number changes, flags, states/actions, resources, strings, weapons and
other rules are not enabled. Supported runtime ranges are positive health/mass,
nonnegative reaction/dimensions, pain chance 0–256 and walking speed 0–32767;
the parser preserves the broader original 32-bit values independently.

The constructor is internal: there is no patch option in the public launcher,
authority or session APIs. Campaign propagation, save/keyframe identity and
network compatibility are still prerequisites for exposing patched sessions.
Focused gameplay tests cover movement, wall collision, damage/pain RNG, overkill,
corpse/raised dimensions, barrel zero bounds, nightmare spawn/respawn behavior,
rejection before RNG changes, and unpatched session isolation. Vanilla definitions
produce the same initial save state and RNG as the existing unpatched constructor.
Runtime/app/network/parser suites pass. These are Go gameplay regressions;
independent DSDA gameplay/demo parity has not yet been established.

## Next integration milestone

Load external patches and embedded lumps in a verified order, carry the immutable
definitions through session construction, and adapt actor/state/weapon consumers.
State actions must work on patched actor types rather than selecting behavior
solely by map Thing number. Then add patch identity to save/keyframe/network
compatibility and verify actual Sunlust MAP30 gameplay against DSDA before
attempting the complete original campaign and cold checkpoints.
